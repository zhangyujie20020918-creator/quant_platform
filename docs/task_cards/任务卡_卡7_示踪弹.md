# 任务卡 · 卡7 示踪弹(玩具策略全流程贯通 → 框架 v1 完工打 tag)

开工:2026-08-28 | 前置:卡6 人类验收放行 | 蓝图:第八节卡7(框架 v1 完工判据 = 示踪弹贯通)| SOP:S0~S5 全链

## 一、定义(做什么)

用同一个玩具策略(沪深300 成分低波 20 只月调)把平台从 S0 想法登记到面板**一条命令跑通**,每个环节的产出与放行判据
都在一份示踪报告里可追溯;跑通即框架 v1 完工,打 tag `v1.0.0`。玩具策略永久保留为回归样例(合成 store 上的测试锁死
其选券/成交/信号,真实数据数字进示踪报告)。本卡不做新研究、不改任何判据。

## 二、机制

### 1. 示踪弹入口 `python -m tools.tracer [--date] [--skip S2,...]`
按 SOP 顺序执行六个环节,每环节 = 一条子进程命令或一个 python 检查,记录退出码/耗时/产出路径,**失败不中断,标红继续**:

| 环节 | 命令 / 检查 | 放行判据(来自各卡) |
|---|---|---|
| S0 想法登记 | 检查 `research/ideas.md` 含 toy_lowvol 一行(可证伪假设 + 数据可得性 + 目标品种) | 行存在且状态非"废弃" |
| S1 数据体检 | `python -m data.quality --date {date}` | 退市/PIT/脏值通过;覆盖率项按卡1 人类核验结论处理(已接受) |
| S2 因子检验 | `python -m factors.run_factor_tests --date {date}` | 对照组通过(阴性非 active、阳性复现基线);样本外已终审者只沿用 |
| S3/S4 回测 + 交叉验证 | `python -m backtest.run_rqalpha_toy --date {date}` | Δ年化 ≤ protocol.cross_engine_tolerance_pct |
| S5 信号 | `python -m signals.run_signal --strategy toy_lowvol` | 合规 orders 文件;数据不新鲜时正确拒绝(记为"拒绝=通过") |
| 面板 | AppTest 无头四屏 | 无异常 |

`tools/tracer.py::run_stages(stages, runner)` 为纯编排(可测试:失败继续、耗时、产出);`write_trace()` 出
`reports/{date}_示踪弹/trace.md`(环节表 + 各产出相对路径 + 总判定)。

### 2. 回归样例
合成 store 上的既有测试即回归样例:`tests/test_toy_lowvol_rq.py`(RQAlpha 成交)、`tests/test_signals.py`(信号选券)、
`tests/test_cn_stock_redlines.py`(红线)、`tests/test_factor_pipeline.py`(裁决)。真实数据数字只进报告,不进测试(数据会更新)。

### 3. 框架 v1 收尾
示踪报告全绿 → CHANGELOG"框架 v1 完工"→ `git tag -a v1.0.0` 并推送 → 看板全部完成。

## 三、判据(放行条件)
- `python -m tools.tracer` 一条命令跑完六环节,trace.md 总判定通过;
- tracer 编排逻辑有测试(假 runner,不触网、不跑长任务);
- ideas.md 有 toy_lowvol 登记;CHANGELOG;tag v1.0.0 已推送。

## 四、验收(人类看什么)
`reports/{date}_示踪弹/trace.md`;`git tag` 见 v1.0.0;看板八卡全完成。

## 五、风险与未知
- S2 约 8 分钟、S3/S4 约 4 分钟、S1 体检读全表约 1~2 分钟——示踪弹一次约 15 分钟;
- S2 的阳性对照第二次运行才是真正的复现检验(基线已建),若不达容差本批作废——如实记录;
- 覆盖率体检项在 2015 股灾年份为假阳性(卡1 已人类核验接受),示踪弹按"已接受"处理但要如实显示。
