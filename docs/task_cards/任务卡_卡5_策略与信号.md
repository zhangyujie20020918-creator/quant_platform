# 任务卡 · 卡5 策略与信号(两原型基类 + 策略包格式 + run_signal → orders CSV 契约)

开工:2026-08-28 | 前置:卡4 人类验收放行 | 蓝图:原则5 策略包契约 / 原则6 基准可配置 / 第八节卡5 | SOP:S3、S5

## 一、定义(做什么)

让"研究产出"有统一交付物——**策略包**(配置 + 信号逻辑 + 风控参数 + 说明书),并让同一份信号逻辑既跑回测
(RQAlpha)又出实盘信号文件(`orders_{date}.csv`,未来执行服务可直接消费)。里程碑:**玩具策略出一份合规信号文件**。
本卡不做执行、不做面板;组合优化/风险模型不在本卡。

## 二、机制(数值全部在策略包 config / 平台 config)

### 1. 两原型基类 `strategies/base.py`
- `Strategy`:构造自策略包;`signal(asof, ctx) -> {symbol: target_weight}`(**纯逻辑,引擎无关**);
  `rebalance_days(cal, start, end)` 按 `params.rebalance` 走 core.calendar(禁止各策略自算调仓日)。
- `CrossSectionalStrategy`(截面选券:universe 内打分选券)/ `TimeSeriesStrategy`(时序配置:固定资产清单上分配权重)。
- `ctx`(SignalContext)接口:`constituents(asof)` / `is_st(symbol, asof)` / `closes(symbol, asof, n)`(≤asof 的最近 n 个
  有效复权收盘)。两个实现:`StoreContext`(store 面板,出信号用)、`RQAlphaContext`(history_bars / is_st_stock,回测用)。
  **同一 signal() 在两种 ctx 下必须给出相同选券**(测试锁死)。

### 2. 策略包格式 `strategies/<id>/`
`config.yaml`(必填:id / name / type / universe / params / benchmark(≥1)/ risk / crash_definition;可选
freshness_max_lag_days 覆盖平台值;status: toy|research|approved,approved_by)+ `strategy.py`(`build(package) -> Strategy`)
+ `说明书.md`(SOP S5 三件套:策略说明书 + 崩溃定义 + config 小节;人类签字前 status 不得为 approved)。
`strategies/package.py::load_package(id)` 校验 schema,缺项/非法即拒。

### 3. 风控参数 `strategies/risk.py::apply_risk(weights, risk)`
`max_weight` 封顶(超出部分不再分配,留现金)、`max_positions` 按权重截断;机制在代码,数值在策略包。

### 4. 信号文件契约 `signals/schema.py`
`orders_{signal_date}.csv` 列:`strategy_id, signal_date, symbol, side, target_weight, ref_price, data_asof, data_lag_days, generated_at`。
语义:文件 = 完整目标组合(未列出的标的目标权重 0);side 固定 long(本平台只做多);target_weight ∈ [0,1] 且合计 ≤ 1;
ref_price = 信号日原始收盘(执行参考,非成交价);`validate_orders(df)` 拒绝不合规文件。

### 5. 出信号入口 `python -m signals.run_signal --strategy <id> [--date YYYY-MM-DD]`
流程:加载策略包 → 交易日历(拒绝周内近似)→ `data_asof` = store 末日,`asof` = 请求日或今日前最近交易日 →
**新鲜度红线**:`data_lag_days` = (data_asof, asof] 内交易日数 > `freshness_max_lag_days`(策略包覆盖 > 平台 data 小节)
→ 拒绝出信号(不落文件);否则 signal_date = data_asof,StoreContext 出权重 → apply_risk → 校验 → 经 core.outputs 落
`reports/{日期}_信号/orders_{signal_date}.csv` + `signal_log.md`(参数/新鲜度/选券清单)。

### 6. 玩具策略改造为第一个策略包 `strategies/toy_lowvol/`
信号逻辑迁入 `ToyLowVol(CrossSectionalStrategy).signal`;`strategies/toy_lowvol_rq.make_strategy` 改为用策略包 +
RQAlphaContext(旧 params 入口保留兼容),卡3 交叉验证测试原样通过 = 回测与出信号同一逻辑的证明。

## 三、判据(放行条件)
- 基类/策略包/风控/契约/新鲜度各有测试(合成 store,不触网);StoreContext 与 RQAlphaContext 选券一致;
- 卡3 的 RQAlpha 玩具策略测试与真实数据交叉验证结论不变;
- 真实数据跑通 `run_signal`,产出合规 `orders_{date}.csv`;数据过期时正确拒绝;
- 玩具策略说明书含崩溃定义,status=toy(非 approved);CHANGELOG。

## 四、验收(人类看什么)
1. `reports/{日期}_信号/orders_{date}.csv` + `signal_log.md`;2. `strategies/toy_lowvol/{config.yaml,说明书.md}`;
3. 测试全绿;4. 回测与信号同逻辑的一致性测试。

## 五、风险与未知
- 交易日历文件只到数据末日,"今日前最近交易日"在日历未延伸时退化为数据末日(新鲜度可能低估),如实标注。
- 信号文件只表达目标权重,不含现有持仓/交易量;执行服务需自行差分。
- 时序配置原型本卡只给基类与测试替身,无真实策略实例。
