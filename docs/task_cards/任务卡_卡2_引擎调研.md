# 任务卡 · 卡2 引擎调研(时间盒:实现精简,不追求完美)

开工:2026-08-26 | 前置:卡1 数据层(数据回补中) | 蓝图:第五节待裁决项 + 第八节卡2

## 一、定义(做什么)

回答一个问题给人类拍板:**A股截面选股回测引擎,自研轻量 vs 移植 RQAlpha,选哪条?**
方法:同一个玩具策略(沪深300成分内选低波20只、月频等权),在两种引擎上各跑一遍,列结构化对比。

**不是**要建成生产引擎(那是卡3);只求"能跑出净值曲线"的最小可运行版,用于对比决策。

## 二、对比维度(三判据 + 附加观察)

| 维度 | 自研轻量 | RQAlpha |
|---|---|---|
| ①数据接入成本 | 直读我们的 store(cache parquet) | 需转 RQAlpha bundle 格式;评估转换工作量 |
| ②A股真实性规则可控性 | 红线清单(前复权/涨跌停/停牌/ST/退市/T+1)逐条我们自己实现 | 看它内置哪些、哪些要 hack、哪些控不了 |
| ③人类读代码顺手程度 | 我们自己的代码 | 框架黑盒程度、文档、调试难度 |
| 附:环境兼容 | 无新依赖 | 与 pandas 2.2.3 是否冲突(独立 .venv_probe 实测) |
| 附:净值一致性 | — | 两引擎同策略净值差异(理想 <2%,差异大则说明口径不同,需解释) |

## 三、判据(交付什么给人类)

- 一份对比报告 `reports/{日期}_引擎调研/engine_comparison.md`:三维度逐条 + 附加观察 + **明确的推荐倾向与理由**(但最终由人类裁决,不替人拍板)。
- 两份可运行代码:玩具策略在两引擎上各一份,能跑出净值。
- RQAlpha 兼容性实测结论(装在独立 `research/engine_probe/.venv_probe`,不进主 requirements)。

## 四、验收(人类看什么)

1. `engine_comparison.md` 三判据对比表 + 推荐 + 理由
2. 两条净值曲线(或数值)并排,差异有解释
3. 人类裁决:走自研 or RQAlpha → 结论写入 CHANGELOG,卡3 按裁决实现

## 五、注意

- 玩具策略只为验证管道,不含任何研究观点;沿用卡7 示踪弹同一策略,避免重复造。
- 时间盒:蓝图定"1 天";实现从简,遇到 RQAlpha bundle 转换成本过高即如实记录为"接入成本高"的证据,不硬啃。
- 依赖数据:需 stock_daily/adj_factor/index_weight(回补中);玩具策略只用沪深300成分,数据量小,回补完成即可跑。
