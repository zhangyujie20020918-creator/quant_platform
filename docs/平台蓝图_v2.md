## 一、定位与边界

- 定位:多品种、多策略的**研究框架**,不是任何单一策略的载体。
- 职能五条(边界,超出即越界):**记录想法 / 数据清洗 / 研发 / 回测 / 生成买卖信号**。
- 明确不做(未来独立项目,不在本平台仓库):实盘执行(xtquant/QMT 对接)、服务器部署、自动下单、可视化以外的运营监控。本平台的终点是信号文件。
- 首发品种包:A股股票 + 债券ETF(仅指第一批接入的品种,不构成平台对品种的任何预设);首期策略原型:**截面选券型**(池内打分排序选N只)+ **时序配置型**(标的间调权重/轮动)。两原型共用一个引擎(见原则3),只是调仓接口不同。
- 资金语境:实盘账户 60 万(QMT 权限已开通),首策略预算 50 万。研究时保持容量意识,但执行不在本平台。

## 二、八条设计原则(平台宪法,违反即打回)

1. **品种即插件(总纲)**:核心层(core/data/factors/strategies/backtest/signals)资产无关。任何品种以"品种包"接入 = 品种规则表条目 + 该品种红线清单 + fetcher注册 + 可选特有模块,**不改核心代码**。可转债若回归,同样按插件接入——可转债适应项目,不是项目适应可转债。
2. **来源不写死**:store 层只认统一 schema;每张表注册主源+备源 fetcher(首发 Tushare 主 / AKShare 备),按优先级取数+字段映射。任何上层代码禁止 import fetcher。(现实动机:共享 token 有失效风险,备源即对冲。)
3. **品种规则表**:T+0/T+1、最小交易单位、费率、涨跌停幅等交易规则挂在标的元数据表上,引擎查表执行,代码零硬编码。股票与债ETF的差异全部消化在这张表里。
4. **阈值不写死**:一切数值判据(协议门槛/容差/新鲜度红线等)集中于 config,文档与代码只写机制;修改自由,但须批前声明+修订记账(见 SOP"阈值治理")。
5. **策略包契约**:研究产出交付物 = 策略包(配置 + 信号逻辑 + 风控参数 + 说明书)。信号文件 schema 从第一天按"未来执行服务可直接消费"设计。
6. **基准可配置**:基准是策略配置里的字段(指数或自定义组合,如股债固定比例),平台不预设任何基准。
7. **产出只经 outputs 服务落盘**(`reports/{日期}_{主题}/` 自动归档;旧项目"报告路径硬编码×6"之债的教训);面板只读 reports,永不写。
8. **每张建设卡以可运行里程碑收尾**;框架 v1 完工判据 = 示踪弹贯通(第八节卡7)。

## 三、目录骨架

```
quant_platform/
├── SOP.md / CLAUDE.md / CHANGELOG.md / config.yaml(.example)
├── core/          # bootstrap(编码/日志统一) | config | calendar(交易日历) | outputs(报告路径服务)
├── data/          # schema注册表 | store(来源无关) | fetchers/{tushare,akshare}/ | quality(体检四项)
│                  # DATA_DICTIONARY.md(字段单位表,S1例行维护)
├── instruments/   # 品种规则表(交易规则元数据) + 标的池构建(universe,独立层,谁都可依赖它)
├── factors/       # registry.yaml + 防挖矿协议 + 检验管线(IC/分组/BH/换手) + alphalens薄封装(T+1口径锁死)
├── strategies/    # 每策略一目录(config+逻辑+说明书);截面/时序两种原型基类
├── backtest/      # 单引擎(查品种规则表) | costs | metrics | 真实性红线验收测试
├── signals/       # run_signal:策略包 → orders_{date}.csv(未来执行服务的输入契约)
├── dashboard/     # Streamlit:回测浏览器 + 因子tear sheet(只读reports)
├── research/      # ideas.md(自有想法登记,S0入口) + papers/(外部来源登记,规则自cb_quant平移)
├── reports/       # 只经core/outputs写入;md入git,run产出目录统一 *_runs/ 后缀排除
├── tests/         # pytest,自带fixture,不依赖真实缓存(纪律平移)
└── tools/         # check_secrets pre-commit扫描(平移)等
```

依赖方向(无环):`core ← data ← instruments ← factors ← strategies ← backtest/signals/dashboard`
(universe 独立成层是旧项目 factors⇄strategy 循环之债的根治方案,新平台从第一天就这么长。)

## 四、从 cb_quant 搬什么(资产清算单)

**搬(思想与制度)**:防挖矿协议全文、SOP骨架、fetcher断点续传+防呆隔离设计模式、测试纪律(fixture化/不依赖真实数据)、pre-commit密钥扫描、GBK/编码 bootstrap 教训、字段单位表实践、按日期归档实践。

**不搬(代码与数据)**:转债回测引擎(品种特化)、strategy 代码、live/台账体系(执行已出界)、净值指纹机制、cache 数据(封存于 cb_quant 原地,转债品种未来启用时再议)。

**cb_quant 处置**:打 archived 标记,只读封存,不再投入任何维护。

## 五、技术选型(已定与待裁决)

- **已定**:Python 3.11 / pandas / Streamlit(面板) / **alphalens-reloaded、quantstats 直接 pip 安装**(A股是其主场;alphalens 必须经平台薄封装调用,T+1 价格对齐锁死在封装入口,裸调用视为违规)/ qlib 不引入(只抄清单,ML 阶段再整体评估)。
- **待裁决(卡2)**:回测引擎 = 轻量自研 vs RQAlpha。时间盒 1 天,同一玩具策略两边各跑一遍,按三判据出对比:数据接入成本 / A股真实性规则可控性 / 人类读代码顺手程度。**人类裁决,平台方无预设立场。**

## 六、数据层(蓝图只定机制,表清单不写死)

- 机制四件:schema注册表 / 主备双源 / 断点续传 / 体检四项(退市样本在否 / PIT 时点 / 脏值 / 覆盖曲线),外加 DATA_DICTIONARY 字段单位表例行。
- **具体拉哪些表不在蓝图定**:卡1任务卡按示踪弹最小需求定首批清单,其后各策略按需追加——框架不预设研究方向。
- 回补起点:config 默认 2010-01-01,可改。
- 放行:体检四项通过才算数据卡收尾。

## 七、真实性红线清单(机制:按品种包挂载,不属于平台核心)

- **机制**:每个品种包必须附带一份红线清单,与品种规则表同处登记;引擎验收测试按清单实例化——新品种=新清单,核心引擎零修改。每条红线对应至少一个验收测试;SOP S4 引用的是"该策略所属品种包的清单",不是任何固定清单。
- 首发实例·A股股票:前复权正确(头号未来函数源)/ 涨停不可买、跌停不可卖 / 停牌口径书面声明 / ST 过滤 / 退市股在历史池 / T+1 / 全成本。
- 首发实例·债ETF:T+0、费率与最小单位按规则表执行;其余条目在卡3实例化时定。
- 可转债若回归:强赎/退市清算等旧红线从 cb_quant 归档报告取材,作为该品种包的清单接入,核心不动。

## 八、建设卡序列(一卡一会话;收尾=测试绿+里程碑可运行+CHANGELOG)

| 卡 | 内容 | 可运行里程碑 |
