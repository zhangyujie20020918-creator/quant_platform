# quant_platform 使用指南(给第一次接手的人)

> 这份文档假设你会用命令行、装过 Python,但没读过本项目任何代码。按顺序做就能跑起来。
> 更深的规则在 `SOP.md`(流程宪法)、`docs/平台蓝图_v2.md`(架构宪法)、`CLAUDE.md`(给 AI 施工的指针)。

## 0. 一分钟认识它

- **它是什么**:一个 A 股量化研究流水线——把"想法"变成"经过检验的因子 → 策略包 → 回测报告 → 每日目标持仓信号文件",
  外加一个网页面板看结果。**它到信号文件为止**,不连券商、不下单。
- **它不是什么**:不是自动交易系统;不预设任何策略观点。自带的"玩具策略"(沪深300 低波 20 只月调)只是用来验证管道的样例,
  **不是投资建议**。
- **数据从哪来**:Tushare(需要你自己的 token,积分档要能拉日线/复权因子/退市股/成分)+ AKShare 备源。所有数据先落本地
  `cache/`,之后的所有环节只读本地,不再联网。
- **一条命令自检**:`python -m tools.tracer` 会把玩具策略从想法登记跑到面板,6 个环节全绿就说明环境没问题。

## 1. 安装(第一次,约 15 分钟)

前置:Windows / Python **3.11**(RQAlpha 要求 numpy<2,项目已锁版本)/ git。

```powershell
git clone https://github.com/zhangyujie20020918-creator/quant_platform.git
cd quant_platform
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy config.example.yaml config.yaml          # 然后编辑 config.yaml,只改 credentials.tushare.token / base_url
printf '#!/bin/sh\nexec .venv/Scripts/python.exe tools/check_secrets.py\n' > .git/hooks/pre-commit   # 密钥防泄漏钩子(Git Bash 里执行)
.venv\Scripts\python -m pytest -q             # 应全绿(不联网,几十秒)
```

下文所有 `python` 都指 `.venv\Scripts\python`。`config.yaml` 永远不进 git(钩子会拦)。

## 2. 目录地图(只需要认识这些)

| 目录 | 作用 | 你会碰到的文件 |
|---|---|---|
| `config.yaml` | **所有数值都在这里**:数据源、阈值、品种规则(涨跌停/费率)、样本切分 | 改阈值 = 先在 CHANGELOG 写"批前声明",再改 |
| `data/` | 拉数据、存数据、体检 | `python -m data.fetch` / `python -m data.quality` |
| `research/ideas.md` | 想法登记表(S0) | 一行一个想法 |
| `factors/` | 因子注册表 + 实现 + 检验管线 | `registry.yaml`、`lib/<id>.py`、`python -m factors.run_factor_tests` |
| `strategies/<id>/` | **策略包**:config.yaml + strategy.py + 说明书.md | 复制 `toy_lowvol/` 改 |
| `backtest/` | 回测引擎(RQAlpha + 本地数据) | `python -m backtest.run_strategy --strategy <id>` |
| `signals/` | 出信号 | `python -m signals.run_signal --strategy <id>` |
| `dashboard/` | 网页面板(只读) | `streamlit run dashboard/app.py` |
| `reports/{日期}_{主题}/` | **一切产出都在这里**,面板读的就是它 | md 报告进 git,`*_runs/` 大文件不进 |
| `tools/tracer.py` | 全流程自检 | `python -m tools.tracer` |

## 3. 数据(第一次全量,之后增量)

```powershell
python -m data.fetch --status                       # 看各表现在到哪一天
python -m data.fetch                                # 首次:8 张表从 2010-01-01 全量回补(几小时,断网可重跑续传)
python -m data.fetch --tables stock_daily,adj_factor,trade_cal   # 平时:只补最近几天(按表)
python -m data.quality                              # 体检四项 → reports/{今天}_数据体检/quality_report.md
```

- 8 张表:交易日历、股票列表(含退市)、日线(不复权)、复权因子、改名(ST)、指数日线、指数成分权重、ETF 日线。
- 体检里"覆盖率"一项在 2015 年会报未通过——那是股灾千股停牌造成的假阳性,已人工核验接受;其余三项必须通过。
- 断网/中断:直接重跑同一条命令,只补缺口。

## 4. 从想法到信号(研究员的六步)

### 第 1 步 · 登记想法(S0)
在 `research/ideas.md` 表里加一行:**一句可证伪的假设** + 数据是否已有 + 目标品种。写不出"怎样算被证伪"的想法不往下走。

### 第 2 步 · 因子(S2)
1. 在 `factors/registry.yaml` 加一条(五要素必填:id / formula / direction / hypothesis / category;讲不出为什么赚钱的不收):
   ```yaml
   - id: my_factor
     name: 我的因子
     category: momentum
     direction: to_be_tested        # higher_better | lower_better | to_be_tested(由样本内 IC 定方向)
     formula: "close_t / close_{t-60} - 1"
     hypothesis: "……(为什么它该有超额)"
     status: candidate
     role: candidate
   ```
2. 写实现 `factors/lib/my_factor.py`:
   ```python
   def compute(ctx):                 # ctx["close"] / ctx["open"] 是 date×symbol 的后复权面板,ctx["cfg"] 是 config
       close = ctx["close"]
       return close / close.shift(60) - 1
   ```
3. 跑检验:`python -m factors.run_factor_tests`(约 8 分钟)。看 `reports/{今天}_卡4因子检验/factor_verdict.md`:
   - 第一节是**批前声明**(阈值、样本内/外切分、候选数)——判据先于数据,不许事后改;
   - 裁决总表每因子一行:`active`(通过全部判据)/ `tested_weak`(有信号但不够)/ `rejected`(无信号);
   - 对照组:随机因子必须不是 active、已知因子(20 日反转)必须复现——任一失败整批作废;
   - **样本外每个因子一生只评一次**,结果自动写回 registry;想"再试试"就是挖矿,平台会拒绝。
   - tear sheet 图在 `tear_<id>_runs/`,面板里能看。

### 第 3 步 · 策略包(S3)
复制 `strategies/toy_lowvol/` 为 `strategies/<你的id>/`,改三个文件:
- `config.yaml`:id、universe(指数成分或固定清单)、params、benchmark(至少一个)、risk(单票上限/持仓数)、
  `crash_definition`(至少一条"什么情况算策略崩溃")、`status: research`;
- `strategy.py`:实现 `signal(asof, ctx) -> {symbol: 目标权重}`。`ctx` 只给你三样东西:
  `ctx.constituents(asof)` 当天的候选池、`ctx.closes(symbol, asof, n)` 最近 n 个复权收盘、`ctx.is_st(symbol, asof)`。
  **同一份 signal() 既用于回测也用于出信号**,不会出现"回测和实盘逻辑不一致";
- `说明书.md`:策略说明 + 崩溃定义 + 签字栏(人类签字前 status 不能是 approved)。

### 第 4 步 · 回测(S4)
```powershell
python -m backtest.run_strategy --strategy <你的id> --start 2011-06-01 --end 2022-06-30
```
产出 `reports/{今天}_回测_<id>/backtest.md`(策略 vs 基准的总收益/年化/回撤/夏普)+ `nav.csv` + `rq_runs/`(完整报表)。
引擎是 RQAlpha,数据是本地 store;涨跌停不可买卖、停牌不可交易、T+1、退市清算、佣金/印花税/过户费都自动在内
(规则和费率在 `config.yaml` 的 `instruments.cn_stock`)。

### 第 5 步 · 出信号(S5)
```powershell
python -m signals.run_signal --strategy <你的id>
```
产出 `reports/{今天}_信号_<id>/orders_{信号日}.csv`:每行一只股票的目标权重(没列出的 = 0),外加参考价、数据日期、
数据落后天数。**数据落后超过 `freshness_max_lag_days`(默认 2 个交易日)会拒绝出信号**——这是故意的,先去更新数据。
这个 csv 就是交给执行端(人或程序)的东西;`status` 不是 `approved` 的策略,信号只供研究,不得用于交易。

### 第 6 步 · 看结果
```powershell
streamlit run dashboard/app.py
```
浏览器自动打开,左侧四屏:**回测浏览器**(净值曲线、回撤、指标、成交、持仓)/ **因子 tear sheet**(裁决表 + 图)/
**信号**(orders 文件)/ **报告**(所有 md)。面板只读 `reports/`,想看到新东西就先跑上面的命令生成报告。

## 5. 全流程自检:示踪弹

```powershell
python -m tools.tracer
```
用玩具策略把 S0→S1→S2→S3/S4→S5→面板跑一遍(约 9 分钟),报告 `reports/{今天}_示踪弹/trace.md`。
6/6 通过 = 环境、数据、引擎、管线都正常。**改了核心代码或换了机器后跑一次**,平时不必。

## 6. 日常运营(每周 1 小时,戴"运营官"帽子)

1. `python -m data.fetch --tables trade_cal,stock_daily,adj_factor,namechange,stock_basic,index_weight` 补最近数据;
2. `python -m data.quality` 看体检;
3. `python -m signals.run_signal --strategy <id>` 出信号(数据不新鲜会被拒 → 回到第 1 步);
4. `streamlit run dashboard/app.py` 看一眼;
5. 有任何判断写进 `CHANGELOG.md`——**对话/口头不算记录**。

## 7. 铁律(违反即打回)

1. 判据先于数据:阈值先写进 config 和批前声明,再看结果;2. 样本外只看一次;3. 对照组必带;4. 终选为空合法
(一个因子/策略都没通过是正常结果);5. 全成本 + 真实性红线(涨跌停/停牌/T+1/退市/ST);6. 数据来源不写死;
7. 变更必记账(改数值 = CHANGELOG 追加,原文不删);8. 对话不是记录;9. 数据不新鲜不出信号;10. 三顶帽子分开戴
(运营 / 研究 / 风控,同一时刻只戴一顶)。

## 8. 常见问题

- **`config.yaml` 和 `config.example.yaml` 结构不一致报错** → 新键要两边都加(example 进 git,yaml 不进)。
- **回补中途断网** → 重跑同一条 `data.fetch`,分片级续传;`cache/fetch_failures.csv` 记着失败过的分片。
- **出信号被拒"数据不新鲜"** → 正常,先补数据;想放宽就改策略包里的 `freshness_max_lag_days`(并记账)。
- **因子想重测样本外** → 不行。改公式 = 新因子(新 id),旧的保留为 rejected/tested_weak,永不删除。
- **测试怎么跑** → `python -m pytest -q`,全部不联网、不依赖你的 cache(用合成数据),应全绿。
- **面板没东西** → 它只读 `reports/`,先跑对应命令生成报告。
- **想接可转债/ETF** → 品种即插件:加规则表条目(config `instruments.*`)+ 红线清单 + 测试,核心代码不动(见蓝图第七节)。
